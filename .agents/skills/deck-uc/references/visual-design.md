# Sistema de dirección de arte e infografía UC — estándar premium

Esta guía define el umbral visual de `deck-uc`. El objetivo no es producir un PowerPoint corporativo correcto: es producir una presentación con **dirección de arte editorial, precisión de consultoría e infografía semántica**, manteniendo la identidad UC.

## 1. El salto de calidad buscado

Una lámina premium no se reconoce por tener más elementos, sino por tener una decisión visual clara. Debe sentirse diseñada como una página editorial: jerarquía precisa, retícula rigurosa, tipografía controlada, espacio negativo, microdetalles consistentes y una visualización hecha para la idea concreta.

Prohibido confundir "infografía" con flechas, chevrons, círculos o cajas genéricas. Un diagrama sólo es válido si su geometría codifica una relación real.

## 2. Regla de dirección de arte

Antes de dibujar cada lámina declarar internamente:

- `message`: qué debe entenderse en 5 segundos;
- `relationship`: qué relación existe entre las ideas;
- `evidence`: qué evidencia mínima debe verse;
- `visual_thesis`: qué forma visual hace visible la conclusión;
- `archetype`: familia visual;
- `composition`: geometría concreta de esta lámina;
- `emphasis`: elemento dominante;
- `reading_order`: recorrido de lectura;
- `density`: sparse | medium | dense;
- `editorial_devices`: kicker, rule, callout, annotation, source, footer, numbering;
- `variation_check`: cómo se diferencia de las 2 slides anteriores.

No construir hasta que `visual_thesis` y `composition` estén definidos. `archetype` por sí solo no basta.

## 3. Mapa relación → visual

| Relación | Visual preferido |
|---|---|
| Secuencia | process flow, chain, stepped path |
| Causa → efecto | causal chain / mechanism map |
| Evolución | timeline / trajectory |
| Madurez | staircase / maturity ladder / continuum |
| Comparación | parallel comparison / aligned small multiples |
| Dos mecanismos | dual-track system |
| Antes/después | transformation |
| Jerarquía | tree / nested hierarchy |
| Arquitectura | layered system / connected architecture |
| Anatomía | annotated object / exploded view conceptual |
| Ciclo | feedback loop |
| Variables cruzadas | matrix / 2×2 / conceptual heatmap |
| Dimensiones | editorial columns / radial only if relationship warrants it |
| Responsables | swimlane |
| Dependencias | dependency map / network |
| Decisión | branching flow / decision logic |
| Métricas | KPI strip + supporting chart |
| Tendencia | chart appropriate to data |
| Evidencia → conclusión | evidence ladder / synthesis composition |
| Alcance | nested boundary / horizon / in-out scope |
| Portafolio | landscape / matrix / grouped map |

Si no existe una relación visual real, usar composición editorial simple. Nunca fabricar una infografía para decorar.

## 4. Prohibiciones de aspecto “PowerPoint genérico”

Evitar salvo necesidad semántica explícita:

- SmartArt-like chevrons repetidos;
- filas de círculos numerados conectados por flechas;
- “tres columnas” como respuesta universal;
- rectángulos grandes con texto centrado;
- cards equivalentes con encabezado + párrafo;
- tablas pesadas con celdas coloreadas;
- mockups de slide dentro de una slide salvo que el contenido sea realmente una interfaz/slide;
- flechas grandes decorativas;
- iconos Office genéricos como elemento protagonista;
- bandas de color grandes sin función;
- cajas con borde grueso;
- bullets como visual principal;
- repetir una misma geometría cambiando sólo el texto.

Si una slide recuerda a SmartArt o a una plantilla prediseñada, rediseñarla.

## 5. Retícula editorial

Trabajar con una retícula estable de 12 columnas (o equivalente proporcional) y márgenes generosos. Toda alineación debe caer en la retícula: título, visual, annotations, takeaway, fuentes y footer.

Principios:
- fondo blanco dominante;
- 55–70% de la superficie puede permanecer vacía cuando la idea lo permita;
- una sola zona de máximo contraste por slide;
- no llenar huecos;
- preferir alineación izquierda;
- usar asimetría controlada cuando mejore jerarquía;
- mantener ritmo vertical constante entre kicker, action title, visual, takeaway y footer.

## 6. Jerarquía tipográfica premium

La tipografía debe hacer gran parte del trabajo visual.

- **Kicker/eyebrow:** pequeño, mayúsculas, espaciado, contextual.
- **Action title:** 1–2 líneas; conclusión completa; dominante pero no sobredimensionada.
- **Deck/section labels:** discretos.
- **Labels de diagrama:** compactos, consistentes.
- **Body:** breve; evitar párrafos.
- **Annotations:** pequeñas y próximas al elemento que explican.
- **Sources/metadata:** secundarias pero legibles.

No usar negrita para todo. Crear contraste con tamaño, peso, espacio y color. Evitar texto enorme sólo para “llenar”.

## 7. Color UC con disciplina editorial

Usar el template oficial como fuente de marca. En contenido:

- azul UC oscuro/medio para estructura y jerarquía;
- cyan para señal secundaria o estados;
- amarillo para un único énfasis, excepción, nodo o momento clave;
- grises fríos para estructura secundaria;
- blanco como superficie principal.

Regla: si más de ~25–30% de una slide de contenido está cubierto por color saturado, justificarlo narrativamente; de lo contrario reducirlo.

No usar amarillo y azul como decoración simultánea en todos los componentes. El color debe tener semántica estable dentro del deck.

## 8. Microdetalle editorial

Para elevar el acabado:
- reglas horizontales de 0.5–1 pt;
- pequeños ticks, brackets, leaders y dotted guides cuando aclaren relación;
- numeración y labels con posición consistente;
- fuentes y notas integradas al grid;
- pequeñas barras de acento, no contenedores masivos;
- estados futuros/hipotéticos mediante outline o dashed stroke;
- conectores finos con puntas discretas;
- esquinas y strokes consistentes;
- micro-iconografía lineal sólo si aporta significado.

## 9. Composición: del arquetipo a una pieza única

No basta decir “timeline”. Diseñar una composición específica para el contenido.

Ejemplo: una madurez 0–5 puede usar alturas crecientes, distinguir alcance actual con relleno sólido, extensión con tint y futuro con outline discontinuo, y añadir una banda inferior que agrupe niveles. Esa geometría comunica alcance sin leer todos los textos.

Ejemplo: una arquitectura puede usar capas a la izquierda y anatomía del objeto a la derecha, conectadas por un único vínculo semántico. No resolverla como dos cajas independientes.

Ejemplo: tres conceptos relacionados pueden ser tres mini-diagramas con gramática común, no tres tarjetas.

## 10. Diagramas

- El grosor de línea debe ser secundario a la información.
- Flechas sólo para dirección, transformación o dependencia.
- Usar proximidad y alineación antes que contenedores.
- Resultados/salidas deben tener mayor peso que pasos intermedios.
- Para loops, mostrar el retorno físicamente.
- Para mecanismos paralelos, conservar una gramática idéntica para comparar.
- Para jerarquías, la posición debe comunicar nivel.
- Para arquitectura, la conexión entre capas debe ser visible.

## 11. Datos y charts

Cuando haya datos reales, priorizar visualización cuantitativa sobre texto descriptivo.

- elegir chart por pregunta, no por estética;
- eliminar gridlines y leyendas innecesarias;
- destacar sólo la serie/punto relevante;
- anotar directamente el insight;
- no usar 3D;
- no inventar escalas ni cifras;
- si no hay datos cuantitativos, no simular un chart.

## 12. Tablas

Las tablas son último recurso para comparación exacta.

- sin bordes verticales por defecto;
- reglas horizontales ligeras;
- alineación precisa;
- encabezado discreto;
- máximo énfasis en 1–2 celdas/filas relevantes;
- si el mensaje es una diferencia, visualizar la diferencia en vez de mostrar toda la tabla.

## 13. Densidad y edición

Una slide premium puede ser densa, pero debe estar editada.

Antes de diseñar, reducir el contenido a:
- una conclusión;
- 3–7 unidades de evidencia visibles, según complejidad;
- una implicancia/takeaway si es necesaria;
- fuente/metadata.

Mover detalle secundario a notas, appendix o una slide posterior. No encoger tipografía para salvar exceso de contenido.

## 14. Variedad narrativa y visual

No repetir la misma familia en slides consecutivas salvo serie deliberada.

En decks de 8+ slides, cuando el contenido lo permita, combinar al menos 4 familias entre:
- editorial statement;
- process/sequence;
- comparison;
- architecture/anatomy;
- maturity/timeline;
- matrix/map;
- chart/data;
- mechanism/cycle;
- table/structured evidence.

Pero la variedad nunca debe ser aleatoria: cada familia nace del contenido.

## 15. Anatomía de referencia

Una slide de contenido premium suele tener:
1. kicker contextual;
2. action title;
3. micro-regla/acento opcional;
4. visual principal ocupando la mayor parte de la zona útil;
5. una implicancia breve, si agrega valor;
6. fuente/metadata;
7. footer/número UC.

No es obligatorio usar los siete elementos. Sí es obligatorio que exista una jerarquía equivalente.

## 16. Identidad UC

`assets/template-uc.pptx` es obligatorio como fuente primaria de identidad. Conservar lockup, proporciones, portada/cierre y elementos institucionales que correspondan.

Pero la marca debe funcionar como **marco**, no como “layout”. Las slides de contenido deben sentirse UC por su sistema de tipografía, color, footer, geometría y disciplina, no porque repitan cajas del template.

## 17. QA visual de tres pasadas

### Pasada A — 5 segundos
- ¿Se entiende la conclusión sin leer el cuerpo?
- ¿Hay un foco dominante?
- ¿La geometría refuerza el mensaje?

### Pasada B — 30–60 segundos
- ¿La evidencia se recorre en orden natural?
- ¿Cada elemento tiene función?
- ¿La relación está codificada visualmente?
- ¿Hay texto que podría eliminarse?

### Pasada C — acabado al 200%
- alineaciones exactas;
- baseline consistente;
- strokes uniformes;
- conectores limpios;
- espaciado óptico;
- tamaños de labels consistentes;
- footer y numeración uniformes;
- cero overflow, clipping o solapes.

## 18. Red flags que obligan a rediseñar

Rediseñar antes de entregar si ocurre cualquiera:
- slide = título + 3 cajas;
- slide = título + bullets sin visual cuando existe relación visualizable;
- SmartArt-like;
- dos slides seguidas con la misma composición;
- más de un foco visual de igual peso;
- color saturado usado como relleno dominante sin significado;
- demasiados bordes;
- tipografía reducida para hacer caber texto;
- visual decorativo que no añade comprensión;
- una infografía que podría cambiar de orden sin cambiar el significado;
- el diagrama no se entiende sin leer todos los párrafos.

## 19. Umbral final

Antes de entregar, preguntarse: **¿esta lámina podría aparecer, sin sentirse fuera de lugar, en un informe visual de consultoría de alta gama, una defensa académica premium o una publicación editorial institucional?**

Si la respuesta es no, iterar composición, edición y microdetalle. No entregar una primera solución funcional como solución final.

## 20. Calibración visual reforzada — moderno, institucional y no "plantilla"

A partir del estándar de salida, aplicar además estas reglas para evitar un resultado correcto pero todavía genérico:

- La identidad UC debe sentirse por **sistema**, no por saturación: lockup, paleta, tipografía, banda/footer, reglas y microdetalle. No convertir el marco azul del template en el protagonista de cada lámina si el master/layout permite una variante institucional más liviana.
- Evitar que todas las slides tengan exactamente la misma silueta `kicker + título azul + diagrama centrado + footer`. Mantener consistencia editorial, pero variar deliberadamente escala, eje, densidad, composición y posición del visual.
- El action title no tiene que ser azul por defecto. Elegir color/peso según jerarquía y contraste del master; el sistema debe ser consistente, no mecánico.
- Reducir el aspecto "manual de capacitación": menos diagramas demostrativos genéricos y más composiciones que hagan visible una conclusión concreta.
- Preferir **diagramas integrados** a listas acompañadas por símbolos. Si texto y visual pueden separarse sin perder significado, la integración es insuficiente.
- Evitar timelines basados sólo en una línea con puntos equidistantes cuando el tiempo/distancia no tiene significado. Usar secuencia editorial, etapas con escala, hitos, bandas o geometría proporcional según el caso.
- Evitar tablas disfrazadas de infografía. Si el mensaje es contraste, diferencia o transformación, diseñar esa diferencia directamente.
- Usar contenedores sólo cuando definan agrupación real. La proximidad, alineación, escala, color y whitespace deben resolver la mayor parte de la organización.
- Los highlights amarillos deben ser escasos y memorables: idealmente un único punto de tensión, decisión, excepción o takeaway por slide.
- Usar azul/cyan/gris con semántica estable a lo largo del deck; no alternar colores sólo por variedad.
- Cuando una slide sea conceptual, buscar una **metáfora espacial sobria**: capas, trayectoria, frontera, puente, embudo, bifurcación, escalera, sistema, tensión, convergencia, etc., sólo si corresponde a la relación real.
- Cuando una slide tenga 4–8 unidades equivalentes, evitar convertirlas automáticamente en 4–8 cards. Explorar eje, mapa, espectro, small multiples, columna editorial, matriz o secuencia.
- Una slide premium debe conservar legibilidad en miniatura: la masa visual y el foco deben ser reconocibles incluso sin leer el texto.

### Profundidad visual

Para cada slide clasificar internamente la profundidad:

- `L1 editorial`: statement, quote, definición o conclusión con composición tipográfica.
- `L2 diagramática`: relación conceptual explícita mediante geometría.
- `L3 analítica`: evidencia, datos, arquitectura o sistema con múltiples capas de lectura.

No hacer todo el deck en L2. Alternar L1/L2/L3 según la narrativa para crear ritmo y sofisticación.

### Regla de singularidad

Antes de construir una slide, responder: **¿qué rasgo visual hace que esta slide sea reconocible frente a las dos anteriores?** Puede ser escala, orientación, densidad, silueta, eje, uso de espacio, tipo de evidencia o foco. Si la respuesta es "el texto cambia", rediseñar.

## 21. Auditoría visual final obligatoria con corrección

La auditoría no es un checklist pasivo. Es un **ciclo obligatorio de inspección -> hallazgo -> corrección -> revalidación** antes de terminar.

### A. Auditoría de deck completo en miniaturas

Revisar todas las slides juntas y detectar:

- monotonía de siluetas;
- exceso de azul o amarillo;
- repetición de timelines, cards, columnas o diagramas equivalentes;
- cambios injustificados de estilo;
- slides visualmente mucho más débiles o densas que el resto;
- falta de alternancia entre slides sparse, medium y dense;
- portadas, divisores y cierres que no respiren como parte del mismo sistema;
- consistencia del marco/footer/lockup UC.

**Corregir** cualquier secuencia de 3 slides que se perciba como la misma plantilla con contenido distinto, salvo serie deliberada.

### B. Auditoría slide por slide

Para cada slide validar y corregir:

1. **Mensaje:** ¿se entiende la conclusión en 5 segundos?
2. **Foco:** ¿existe un único elemento dominante?
3. **Relación:** ¿la geometría expresa la relación sin depender de párrafos?
4. **Edición:** ¿puede eliminarse 15–30% del texto visible sin perder evidencia esencial? Si sí, editar.
5. **Composición:** ¿el visual ocupa una proporción adecuada y no queda flotando en exceso de espacio sin intención?
6. **Jerarquía:** ¿kicker, título, labels, evidencia, takeaway y fuentes tienen niveles inequívocos?
7. **Modernidad:** ¿hay recursos que recuerdan SmartArt, plantilla de capacitación o PowerPoint predeterminado? Si sí, rediseñar.
8. **UC:** ¿se reconoce la identidad institucional sin que la marca compita con el contenido?
9. **Microdetalle:** ¿strokes, conectores, radios, baseline, márgenes y espaciados son consistentes?
10. **Notas:** ¿el guion permite presentar la slide y coincide con lo que finalmente quedó visible?

### C. Auditoría técnica/render

Cuando la plataforma permita renderizar o inspeccionar el archivo final:

- renderizar todas las slides;
- revisar miniaturas y cada slide a tamaño completo;
- verificar clipping, overflow, solapes, saltos de línea extraños, elementos fuera del safe area, conectores desalineados y fuentes sustituidas;
- comprobar que diagramas, gráficos y textos siguen siendo editables cuando el formato lo permita;
- corregir todos los defectos encontrados y volver a renderizar las slides afectadas.

No considerar finalizada la presentación hasta completar al menos una segunda inspección de las slides corregidas.

### D. Scorecard interno de salida

Evaluar internamente cada slide de 0 a 2 en estas 8 dimensiones:

- claridad del mensaje;
- fuerza de la tesis visual;
- jerarquía;
- edición/síntesis;
- sofisticación compositiva;
- coherencia UC;
- acabado técnico;
- calidad del guion.

`0 = falla`, `1 = aceptable`, `2 = premium`.

**Regla de entrega:** ninguna dimensión puede quedar en 0 y una slide debe alcanzar al menos **13/16** para aprobar. Las slides hero, resumen ejecutivo, argumento central y cierre deben alcanzar **14/16**. Si no alcanzan el umbral, corregir y volver a auditar. Este score es interno; no mostrarlo salvo que el usuario lo pida.

### E. Validación final

Sólo después de corregir y revalidar, confirmar internamente:

- narrativa aprobada;
- diseño aprobado;
- coherencia UC aprobada;
- render/apariencia aprobados;
- guion completo y sincronizado con cada slide;
- fuentes y evidencia trazables.

La auditoría termina con una decisión binaria interna: `APPROVED` o `REVISE`. Nunca entregar en estado `REVISE`.
